# Huli Ko — project rules

Fisheries traceability and coastal resource management for small-scale fishers in Marinduque, Philippines.
This repo holds the Supabase backend, the admin dashboard (`/admin`), and — in a later phase — the fisher mobile app. Shared logic lives in `/lib` so the mobile app can reuse it.

## Stack (do not substitute without asking)
- Next.js 14 App Router + TypeScript (strict)
- Tailwind CSS v3 + shadcn/ui (CLI pinned to `shadcn@2.3.0`) + lucide-react
- Supabase: Postgres + PostGIS, Auth, Storage, RLS; `@supabase/ssr` for clients
- TanStack Table, Recharts, Leaflet + react-leaflet v4, leaflet-draw, leaflet.heat
- zod for validation, sonner for toasts

## Design rules
- Palette: deep navy (primary/surfaces), teal (accent/positive), sand (neutral backgrounds), coral (alerts only).
  Zone colors are fixed: restricted = red, safe = green, pollution = purple, sanctuary = teal.
- lucide-react icons only. No emojis, no gradients, no glassmorphism, no decorative blobs.
- Desktop-first, dense but readable; responsive down to tablet. 8px spacing grid (Tailwind 2/4/6/8…).
- Real hierarchy: one clear page title, section headings, muted secondary text. Tabular numerals for figures.
- Status always = color + icon + word. Never color alone.
- Every table and chart has a loading skeleton, an empty state and an error state.
- Wording for flagged catches is "for review" / "flagged for review" — never "guilty", "illegal" or "violator".
- Real Marinduque places and species. No lorem ipsum. Never invent statistics; seeded figures are labeled SAMPLE DATA.

## Data and privacy
- Exact catch coordinates are visible to admins only. Public pages show municipality-level area only.
- No secrets in code. Keys live in `.env.local`. `SMS_WEBHOOK_SECRET` is server-only (never `NEXT_PUBLIC_`).
- The app uses only the publishable key. Privileged writes go through narrow SECURITY DEFINER functions
  (e.g. `ingest_sms_catch`), not a service/secret key.

## Code conventions
- Database types come from `lib/database.types.ts` (generated by `supabase gen types`; never hand-edit after first generation).
  Domain aliases live in `lib/types.ts`.
- Flag reason codes are defined in SQL (`evaluate_catch`) and mirrored in `lib/catch/flags.ts`. Change both together.
- Keep components small; shared UI states in `components/data/`, map pieces in `components/map/`.
- Leaflet components are client-only (`dynamic(..., { ssr: false })`).
- Run `npm run build` and fix type errors before finishing each step.
